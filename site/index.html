RECORRIDO PÚBLICO

Prueba el flujo en cinco pasos.

  1. Crea una operación en NexusCore.

    Usa un título reconocible, por ejemplo «Entrega de prueba», y un monto ficticio de $100.

  2. Avanza su estado hasta Completada.

    Pasa por En curso. Cada cambio incrementa la revisión del registro.

  3. Descarga «Exportar eventos».

    El JSON contiene las instantáneas de todas las operaciones, aunque haya filtros activos.

  4. Abre NexusInsight y elige «Importar eventos».

    Selecciona el archivo descargado. Busca tu operación y revisa los indicadores y el CSV.

  5. Repite la importación.

    El total no vuelve a aumentar. Una revisión antigua tampoco reemplaza una más reciente.

El intercambio en Pages es manual.

Cada demo mantiene su conjunto en localStorage con una clave diferente. No hay sincronización automática entre pestañas. Para enviar cambios posteriores, exporta e importa otra vez. Los indicadores incluyen la muestra inicial y los registros que incorpores; el valor completado no equivale a ingresos contables.

INTEGRACIÓN ENTRE SERVICIOS

El mismo contrato, transporte HTTP.

NexusCore
Operación + outbox→Relay HTTP
Reintentos + checkpoint→NexusInsight
Inbox + indicadores

Entrega y consistencia

Core escribe el registro y su evento en una sola transacción. El relay consulta los eventos y entrega lotes a Insight. Solo confirma el cursor después de una respuesta exitosa.

Insight deduplica el identificador del evento y actualiza la instantánea solo con una revisión superior. Así tolera reenvíos sin doble conteo.

Autonomía de cada producto

Cada API conserva su propia base PostgreSQL. Core funciona sin consumidores; Insight admite la muestra u otra fuente compatible. El flujo va de Core hacia Insight y no modifica Core desde el análisis.

GitHub Pages aloja las interfaces. Para ejecutar las APIs y el relay sigue la guía local; las interfaces todavía no llaman a sus APIs.
